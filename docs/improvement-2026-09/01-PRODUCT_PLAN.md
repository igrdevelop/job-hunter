# Product Plan — от личного инструмента к продаваемому продукту

**Status:** draft
**Date:** 2026-09-09
**Роль:** продакт-оунер
**Motivation:** пять месяцев разработки, 459 коммитов, ~3000 тестов, живой прод на VPS,
и ноль внешних пользователей. Существующий `docs/SAAS_PIVOT_PLAN_supersedes_PYTHON_CORE_PLAN.md`
(2026-08-12) отвечает на вопрос «что строить»; этот документ отвечает на вопрос
«для кого, зачем и в каком порядке проверять гипотезы, прежде чем строить».
Он не заменяет план пивота, а ставит перед его Stage 1 продуктовую фазу 0.

---

## Problem

1. **Ценность продукта не измерена.** Вся генерация построена вокруг числа
   `ats_verdict` (независимый вердикт судьи по PDF), под него написан refine-цикл на
   5 раундов (`ATS_VERDICT_MAX_REFINES=5`). Вопрос «предсказывает ли вердикт
   ответ работодателя» поставлен в `docs/review-2026-07/02-next-steps.md` п. 6
   ещё в июле, инструмент `tools/verdict_funnel_corr.py` написан, ответа нет.
   Если корреляции нет, продукт продаёт число, которое ничего не значит.
2. **ICP не назван.** План пивота говорит «resume tailoring», но не говорит кому.
   Сеньор-фронтендер в Польше, любой IT-специалист в ЕС, любой соискатель в мире:
   это три разных продукта с разной ценой, каналами и конкурентами.
3. **Спрос не подтверждён ни одним посторонним человеком.** Мультитенантность
   (`/link`, `users/{uid}/`, profile store M1–M4, preview) уже позволяет посадить
   второго пользователя, но этого ни разу не сделано.
4. **Категория переполнена.** Teal, Rezi, Kickresume, Jobscan, Simplify, LazyApply,
   Huntr: «AI резюме под вакансию» стоит один промпт. Без явного дифференциатора
   продукт конкурирует ценой с бесплатным ChatGPT.
5. **B2C-соискатель как плательщик слаб.** Поиск работы эпизодичен (1–3 месяца раз в
   2–3 года), готовность платить низкая, churn после найма 100%. Это известное
   свойство рынка, а не гипотеза.

## Что действительно нельзя скопировать промптом

Ранжировано по защищённости.

| # | Актив | Где в коде | Почему это ров |
|---|---|---|---|
| 1 | Данные спроса рынка: 25 скрейперов, `job_posting.txt` корпус, `source_health` | `hunter/sources/*`, `Applications/**/job_posting.txt` | Ни один западный конкурент не парсит justjoin/nofluff/pracuj/theprotocol |
| 2 | Честность: судья-антифабрикация + независимый вердикт по отрендеренному PDF | `hunter/claim_judge.py`, `hunter/ats_pdf_roundtrip.py` | Доверие рекрутеров к «AI-резюме» падает; «не врёт» станет требованием |
| 3 | Замкнутая воронка с реальными исходами (sent → confirmed → answered) | `hunter/funnel.py`, колонки `confirmation`/`answer` | Никто из конкурентов не знает, что случилось с CV после скачивания |
| 4 | Двуязычный PL/EN контур: language gate, PL-зеркало, RODO-клауза | `hunter/pipeline/lang.py`, `generate_docs.py` | Локальная специфика, которую глобальный продукт не сделает |
| 5 | Пред-оплатный скор за $0 | `hunter/ats_checker.py` (75% keyword + 25% TF-IDF без LLM) | Готовый лид-магнит, стоимость лида ≈ 0 |

Вывод: дифференциатор № 1 и № 4 диктуют географию (Польша/CEE), № 2 диктует
позиционирование (honest tailoring), № 5 диктует верх воронки.

## Non-goals

- Не продавать поиск вакансий (hunt) в первой версии: подтверждаем решение плана
  пивота §3.1. Причины: юридический риск скрейпинга для коммерческого продукта,
  зависимость от процесса бота, поддержка 25 скрейперов как SLA.
- Не строить биллинг до подтверждения спроса (Stage 7 плана пивота остаётся
  последним).
- Не делать шаблонизатор дизайна CV (план пивота §5, отвергнуто: один ATS-макет).
- Не переписывать существующие планы (`SAAS_PIVOT_PLAN`, `RESUME_PROFILE_STORE_PLAN`,
  `PROFILE_PAGE_TABS_WORKORDER`): они остаются исполнительными документами.

## M0 — Measure (0 кода, 2–3 недели календарных)

Три измерения, каждое с правилом решения, заявленным до запуска.

### M0.1 Вердикт против исходов

```bash
docker compose exec job-hunter python tools/verdict_funnel_corr.py
docker compose exec job-hunter python tools/verdict_noise.py --n 20 --k 3
```

Правило: если доля `answered` в полосе 95+ не выше доли в полосе 85–89 хотя бы
на величину шума судьи (`verdict_noise` даёт sigma), то `ATS_VERDICT_TARGET`
опускается до 85 и `ATS_VERDICT_MAX_REFINES` до 2. Это минус 2–3 раунда на
вакансию и прямое удешевление каждой генерации. Если сигнал есть, число
становится центральным обещанием продукта («мы поднимаем ваш скор с X до Y, и
Y коррелирует с ответами»).

Ограничение: ~700 строк, из них отправлено меньше, ответов ещё меньше. Ответ
будет «слабый сигнал / нет сигнала», не «доказано». Этого достаточно для
решения о цели refine-цикла, недостаточно для маркетингового утверждения.
Формулировку для сайта даст только внешняя выборка (M0.3).

### M0.2 Воронка по источникам

```
/funnel 90
```

Правило: источник с `sent = 0` за 90 дней при `tracked > 20` отключается через
`<SOURCE>_ENABLED=false`. Каждый скрейпер стоит поддержки, и в продукте с
платным market-aggregate тарифом каждый лишний источник это и юридический
риск (см. `07-COMPLIANCE_PLAN.md`).

### M0.3 Concierge-тест на 5 внешних людях

Самое дешёвое подтверждение спроса, весь код уже есть.

1. Найти 5 человек из целевого сегмента (см. ICP ниже): знакомые фронтендеры
   и смежные IT-роли в Польше, активно ищущие работу.
2. Каждый: регистрация на `job-hunter.igrflex.work`, загрузка CV через profile
   store (`upload-resume-dialog`), экран подтверждения, `/link` в Telegram.
3. Владелец вручную (через `/force` или пасту URL от их имени) прогоняет по
   3–5 вакансий на каждого в течение двух недель. Никакого биллинга.
4. Через две недели: короткое интервью (30 минут) по скрипту ниже и таблица.

Что фиксируется на каждого:

| Поле | Зачем |
|---|---|
| Сколько документов сгенерировано | объём |
| Сколько из них человек реально отправил | главный сигнал: если не отправляют, ценности нет |
| Правил ли текст перед отправкой, что именно | качество генерации глазами клиента |
| Сколько ответов/интервью | исход (n мал, но направление видно) |
| Сколько бы заплатил за одно резюме / за месяц | ценовая гипотеза |
| Что было непонятно на экране подтверждения профиля | UX парсера |

Правило: **если меньше 3 из 5 отправили хотя бы одно сгенерированное CV без
правок или с косметическими правками, план пивота Stage 1–8 замораживается** и
следующая итерация посвящается качеству генерации, а не инфраструктуре. Если 3+
отправили, идём в M1.

Скрипт интервью (10 вопросов): как искали работу до этого; чем пользовались
(ChatGPT? Teal? ничем?); что не так с их текущим CV; что сделали с нашим
документом; что смутило; что бы удалили; что добавили бы; заплатили бы; сколько;
кому бы посоветовали.

## ICP и сегментация

Гипотеза сегмента, которую M0.3 подтверждает или опровергает.

**Первичный ICP (B2C wedge):** разработчик / тестировщик / DevOps в Польше,
middle-senior, ищет работу активно, подаётся на 20+ вакансий, двуязычный контур
PL/EN. Боль: каждое резюме под вакансию это 40 минут, а ATS-фильтры отсеивают
до человека. Именно та боль, которую владелец решал для себя.

**Вторичный ICP (B2B2C, кандидат в основной):** организации, через которые
проходят когорты соискателей и которые платят за результат трудоустройства:

| Тип | Почему платят | Как продаётся |
|---|---|---|
| IT-буткемпы (Coders Lab, Kodilla, Future Collars, SDA) | Employment rate это их маркетинг | Лицензия на когорту, 30–100 мест |
| Outplacement-агентства | Клиент-работодатель оплачивает трудоустройство уволенных | Лицензия на компанию |
| Карьерные коучи | Продают часы; инструмент экономит их время | Партнёрская ставка |
| Университетские career centers | Бюджет есть, KPI трудоустройства | Годовая лицензия |

B2B2C решает три проблемы B2C сразу: платёжеспособность, churn (когорты
идут одна за другой), канал (одна продажа даёт 50 пользователей). Цена ошибки:
sales-цикл 1–3 месяца и требования к безопасности данных (см. `05-SECURITY_PLAN.md`).

Решение по сегменту принимается после M0.3: B2C-интервью покажут, готов ли
индивидуал платить; параллельно два-три разговора с буткемпами (без продукта,
только проблема) покажут, есть ли там боль.

## M1..Mn — Milestones

### M1 — Продуктовые метрики и события (до любой новой фичи)

Что: единый event log действий пользователя и пайплайна, чтобы каждый
последующий вопрос имел данные. Схема и место хранения проектируются в
`08-DATA_EVAL_PLAN.md`; здесь только продуктовый список событий:

`profile_uploaded`, `profile_confirmed` (с числом правок парсера),
`vacancy_submitted` (url/paste/both), `prescore_shown` (значение),
`tailoring_started/finished` (verdict, cost, duration), `document_downloaded`,
`document_sent` (пользователь отметил), `outcome_reported` (ответ/интервью/оффер),
`telegram_linked`.

Тест: событие пишется в каждом из существующих путей (URL paste, Apply-кнопка,
web upload). Откат: запись событий обёрнута в `best_effort("events")`.

### M2 — Замкнуть петлю исхода

Что: спросить пользователя, что случилось. Сейчас `confirmation`/`answer`
заполняются владельцем через `/check_responses` из его Gmail (продаваться не
будет, см. план пивота §3.4). Для клиентов нужен явный вопрос: через 7 и 21 день
после `document_downloaded` бот/письмо спрашивает «Отправили? Был ответ?
Интервью?» с тремя кнопками. Ответ пишется в `outcome_reported`.

Зачем: без этого продукт никогда не узнает, работает ли он. Это же данные для
маркетингового утверждения «X% пользователей получили ответ».

Тест: отложенное напоминание создаётся при `document_downloaded`, не
дублируется, отменяется при ответе. Откат: выключатель `OUTCOME_PROMPTS_ENABLED`.

### M3 — Бесплатный пред-скор как публичная страница

Что: страница без регистрации «загрузи CV + вставь вакансию → скор + 5 главных
пропусков». Только `ats_checker.check(run_llm_review=False)`, $0. Результат
показывает пробел, кнопка «улучшить» ведёт в регистрацию.

Зачем: верх воронки с нулевой себестоимостью лида (детали канала в
`02-MARKETING_PLAN.md`).

Тест: скор на странице совпадает со скором CLI `python -m hunter.ats_checker`
на тех же файлах. Откат: страница за feature-флагом сайта. Ограничения: rate
limit по IP (см. `05-SECURITY_PLAN.md`), файлы не сохраняются, TTL 0.

### M4 — Онбординг как продукт, а не как форма

Profile store (M1–M4 + preview) уже даёт upload → parse → confirm → render →
test-resume. Чего не хватает с точки зрения PO:

- **Время до первого документа** как метрика: цель < 10 минут от регистрации.
- **Прогресс-индикатор** из 4 шагов на сайте (профиль → подтверждение → вакансия
  → документ), с возвратом на незавершённый шаг.
- **Правки парсера** считаются: если медиана правок на экране подтверждения > 5,
  парсер (`prompts/resume_parse.md`) требует доработки раньше любой другой фичи.
- **Preview-резюме как «wow-момент»**: показывать сразу после подтверждения,
  до первой вакансии.

### M5 — Ценностная упаковка результата

Сейчас пользователь получает PDF и число. Продукт должен показывать «до/после»:

- скор до (M3) и вердикт после;
- список закрытых ключевых слов (уже есть в `gap_report`);
- список «to_learn» как честный совет, а не как скрытый долг;
- явный дисклеймер «сгенерировано с проверкой судьёй; проверьте факты» (см.
  `07-COMPLIANCE_PLAN.md`).

### M6 — Ценовые эксперименты (после M0.3, до биллинга)

Гипотеза цены проверяется без платёжки: страница тарифов с тремя вариантами и
кнопкой «Оформить», которая ведёт на «мы откроем доступ в течение дня, оставьте
email». Считаем клики по вариантам.

Кандидаты (для B2C, PLN как основная валюта):

| Вариант | Цена | Что внутри |
|---|---|---|
| Free | 0 | пред-скор, 1 tailoring в месяц с водяным знаком |
| Pack | 49 PLN | 10 tailorings, без срока |
| Season | 89 PLN / 3 мес | безлимит с fair use 60/мес, market-aggregate отчёт |

Себестоимость одного tailoring $0.13–0.17 API (README) плюс refine-раунды;
даже при $0.40 полной стоимости маржа в Pack выше 85%. B2B2C цена
формируется отдельно: 20–40 PLN за место в когорте.

### M7 — Только теперь Stage 1–3 плана пивота

Продуктовые предпосылки выполнены: есть подтверждённый спрос (M0.3), есть
метрики (M1), есть петля исхода (M2), есть верх воронки (M3). Дальше
исполняется `SAAS_PIVOT_PLAN` в его порядке с поправками из
`03-ARCHITECTURE_PLAN.md` (Postgres раньше, API-only для клиентов).

## Risks

| Риск | Чем ловится |
|---|---|
| M0.3 покажет «не отправляют» и работа последних месяцев окажется преждевременной | Это успешный исход измерения; план сам предписывает заморозку инфраструктуры |
| Пять знакомых не репрезентативны (вежливые ответы) | Метрика «отправил ли» поведенческая, не опросная |
| Владелец продолжит строить инфраструктуру параллельно с M0 «раз уж есть план» | README серии фиксирует порядок: M0 продукта блокирует Stage 1 пивота |
| B2B2C потребует SSO/SOC2-подобных требований | Не обещать раньше `05-SECURITY_PLAN.md` M3+ |
| Бесплатный пред-скор станет ботом для скрейпинга нашего скора | rate limit + без хранения файлов |

## Cost

M0–M3 не добавляют LLM-вызовов. M2 добавляет Telegram-сообщения и письма.
Concierge-тест: 5 человек × 5 вакансий × ~$0.40 ≈ $10.
